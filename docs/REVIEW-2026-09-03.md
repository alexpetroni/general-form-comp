# formcomp — critical review, 2026-09-03

Reviewed at commit `e9f059b` (v0.2.1, branch `main`). Verified state at that commit:
`npm run check` → 0 errors, 11 warnings; `npm run test:unit` → 27 tests green; the Playwright
suite was not run as part of this review. Every finding below has an id (`R-n`) that the
phase files under `docs/phases/` cite. Line numbers are relative to `e9f059b`; after
PHASE-0 applies the vendored 0.3.0 patch some of them shift — grep for the quoted code.

Overall: the logic core (condition evaluator, validator, fixpoint collection, payload
builder) is clean, tested and documented. The weak spots are on the component side: a few
real bugs, a thin accessibility layer, API surface that promises more than it delivers,
and a fork of this library that already moved ahead (R-25).

---

## A. Bugs

### R-1 — A `likert` question outside a `likert-batch` group renders nothing
`src/lib/components/core/QuestionRenderer.svelte:40-183` has branches for every
`QuestionType` except `'likert'`, and `validateConfig` does not warn. Scenario: a config
puts `{ type: 'likert', required: true }` in a default (`individual`) group → nothing is
rendered, and Next is blocked forever with "Please complete the required fields" pointing
at an empty group. Fix: render a single-question `LikertGroup` from `QuestionRenderer`
(it reads state from context, so `questions={[question]}` works) and add a config check.

### R-2 — Reloading mid-form flashes the wrong step under SSR (verified)
`src/lib/state/form-state.svelte.ts:34-49` reads storage inside `createFormState`, i.e.
during component init. The server has no storage and renders step 1; the client
constructs the state with the persisted index and hydrates a different step. Probe
(`docs/phases/reference/hydration-probe.mjs` against `vite dev`, conditional example,
after completing step 1): server `<h2>` = "Travel Preferences", hydrated `<h2>` =
"Trip Details", no console warning (Svelte patched the DOM silently). Users see step 1
paint, then jump to step 2; interactions before hydration land on the wrong step. Fix:
hydrate from storage after mount (a `hydrate()` method on the controller, called from an
`$effect` in `MultiStepForm`), move the snap-back block
(`MultiStepForm.svelte:68-81`) after hydration, and document the behaviour.

### R-3 — No `reset()`, and persisted answers survive a successful submit
`FormStateController` (`src/lib/types.ts:225-230`) has no reset; `submitForm`
(`MultiStepForm.svelte:142-209`) never clears storage. Scenario: submit → success screen →
reload → the form is back on the last step with every answer filled and Submit enabled;
`submitState` is component-local so a second POST is one click away. Fix: `reset()` on
the controller (clears responses, index 0, deletes the storage entry synchronously and
cancels a pending debounced save); call it after a successful submission once the payload
for the success screen has been captured.

### R-4 — Without `config.submit`, Submit goes dead after one click
`MultiStepForm.svelte:145-150`: `onFormComplete` fires once behind the `completed` flag,
then `if (!config.submit) return;` — no success state, no feedback, button still enabled
and inert. Fix: treat "no submit config" as a submission whose transport is the callback:
`onFormComplete` may return a promise; show the submitting state while pending, then the
built-in success screen / `success` snippet, and `reset()`; on rejection show
`submitErrorMessage`, fire `onSubmitError`, allow retry (`completed` must clear so the
callback fires again).

### R-5 — Number inputs silently clamp, making `invalid` unreachable from the UI
`src/lib/components/inputs/NumberInput.svelte:35-37` and
`RangeInput.svelte:48-49` rewrite an out-of-range value to the bound on `change`, so
`questionStatus` never sees an invalid number; only an inverted range reaches the
`invalidMessage` path (the e2e test at `tests/multi-step-form.spec.ts:110-127` admits
this in its own comment). Typing 999 for "age" silently becomes 120. Fix: store what the
user typed (still `undefined` on empty/NaN), let validation reject it with the configured
message and a red ring on that field.

### R-6 — `inputType: 'email' | 'url'` is decorative
`<form novalidate>` (`MultiStepForm.svelte:267`) disables the browser's check and
`questionStatus` (`src/lib/validation/validator.ts:23-48`) has no text-format branch. The
vendored 0.3.0 copy (R-25) already adds email validation (`isValidEmail`, pattern
`/^[^\s@]+@[^\s@]+\.[^\s@]+$/`); `url` remains unvalidated in both copies.

## B. Accessibility

### R-7 — Likert radios have no usable accessible name on desktop
`src/lib/components/inputs/LikertGroup.svelte:78-79`: the option label is
`<span class="sm:hidden">` (display:none ≥ sm) and the visible desktop content is
`&bull;`, so the computed name of each radio is "•". Rows are not grouped
(`fieldset`/`legend` or `role="radiogroup"` + `aria-labelledby`), so the statement is not
announced either. Fix: `sr-only` for the label text on desktop, one radiogroup per row.

### R-8 — Required / invalid state is not exposed; tooltip is hover-only
No `aria-required` on required controls, no `aria-invalid` on failing ones, no
`aria-describedby` to the `role="alert"` message
(`src/lib/components/layout/QuestionGroupWrapper.svelte:43-47`), no visual required
marker. `FieldLabel.svelte:27-37` renders the tooltip as a non-focusable `title` span:
keyboard and touch users never see it. Also `warning` is passed to every question in the
failing group (`GroupRenderer.svelte:85`), not only the failing ones.

### R-9 — DOM ids are raw question ids
Inputs use `id={name}` with `name = question.id`; group wrappers use
`formcomp-group-{id}`. Two forms on one page, or a host element with the same id, collide
and break label→input association. Svelte ≥ 5.20 offers `$props.id()` for a per-instance
prefix.

### R-22 — Progress landmark label is hardcoded
`src/lib/components/layout/ProgressBar.svelte:18`: `aria-label="Progress"` bypasses
`translate`.

## C. API and design

### R-10 — `renderMode: 'inline'` and `'individual'` render identical markup
`GroupRenderer.svelte:74-87`: the only difference is the `warning` prop; the README
describes two layouts. Deprecate `inline` (alias of `individual`) or make it differ.

### R-11 — `TranslateFn` advertises `params` that are never passed
`src/lib/types.ts:214` vs `src/lib/i18n.ts:9-12` and every call site. Drop the parameter
from the type (a narrowing; two-argument functions still fit).

### R-12 — The POST is not configurable *(backlog)*
`MultiStepForm.svelte:157`: no `credentials`, no timeout/AbortController; consumers
cannot substitute their own transport. See `docs/phases/BACKLOG.md`.

### R-13 — `Question` is one bag of optional props; `validateConfig` gaps
A discriminated union per type is the real fix (backlog). Cheap wins now, in
`src/lib/validation/config-check.ts`: a step `condition` that references its own step
(the README says it must not); `equals`/`not-equals` with a value whose type does not
match the target question (a `scale` stores numbers, options store strings); a value not
among the target's option values; `includes`/`not-includes` on a non-`multi-select`
target; `greater-than`/`less-than` on a non-numeric target; `equals` on a `range` target
(object identity, never true); empty `steps`, a step without groups, a group without
questions; a non-`likert` question inside a `likert-batch` group.

### R-14 — Hidden-answer clearing differs within vs across steps *(backlog)*
`GroupRenderer.svelte:51-60` clears answers of hidden questions only for mounted groups.
Cross-step hides are cleared lazily when the target step mounts, so persisted state and
`allResponses` disagree with what the user sees until then (the fixpoint in
`collectResponses` masks it at submit).

### R-15 — `createFormState` defaults
`form-state.svelte.ts:23`: `version` does not default to `config.version` (the examples
route persists without one, so a config bump does not invalidate its state); the storage
key defaults to a single shared `'formcomp-state'` for every form on an origin (backlog).

### R-26 — `onSubmitError` receives a bare `Error`
`MultiStepForm.svelte:177`: `new Error(\`Request failed (${res.status})\`)` — status and
the parsed body are discarded. Export a `SubmitError` carrying `status` and `data`.

### R-23 — Callback edge cases
`goTo` (`MultiStepForm.svelte:91-100`) fires `onStepChange` even when `goToStep` was a
no-op (out-of-range index); `handleNext` (`:127-139`) duplicates the `onStepComplete`
call in both branches.

## D. Repo hygiene

### R-16 — 11 `state_referenced_locally` warnings
`FormStep.svelte:16` and `MultiStepForm.svelte:28,29,44,45,49,70,72,74`. Intentional
capture-once reads; the vendored copy (R-25) already suppresses them with
`svelte-ignore` comments and derives `settings`. After PHASE-0 the gate runs
`svelte-check --fail-on-warnings`.

### R-17 — The home page inlines a copy of the sleep-assessment example
`src/routes/+page.svelte:6-344` duplicates `src/examples/sleep-assessment.ts` (same ids).

### R-18 — The favicon ships in the package
`src/lib/assets/favicon.svg` → `dist/assets/favicon.svg` (imported from
`src/routes/+layout.svelte:2`).

### R-19 — `package.json` metadata
No `license` (LICENSE is BSD-3-Clause), `description`, `repository`, `keywords`,
`engines` (`.npmrc` sets `engine-strict=true` with nothing to enforce), `sideEffects`,
and `CHANGELOG.md` is not in `files`.

### R-20 — `form-state.svelte.ts` cannot be unit-tested
`vitest.config.ts` has no Svelte plugin and no DOM environment, so `$state` does not
compile and `sessionStorage` does not exist in tests. Persistence, version invalidation
and index clamping are untested.

### R-21 — README "Project structure" is stale
Missing `SummaryStep`, `SelectInput`, `DateInput`, `RangeInput`, `FieldLabel`,
`submission.ts`, `format.ts`, `i18n.ts`, `config-check.ts`, `styles.ts`, `utils.ts`,
`theme.css`, `src/examples/`, `src/routes/examples/`.

### R-24 — Misnamed e2e test
`tests/multi-step-form.spec.ts:110` "out-of-range number blocks progression" tests the
empty-required path, not an out-of-range value (see R-5).

## E. Divergence

### R-25 — The vendored copy in better-sleep-v15 is at 0.3.0 and was never upstreamed
`better-sleep-v15/packages/formcomp` (commits `be84dde`, `59676a1`, `9e79761`,
`c32d504`, `f8ce301` there) adds: email-format validation (`isValidEmail`), a `consent`
question type (`ConsentCheckbox.svelte`, boolean answer, `required` ⇒ must be `true`),
an opt-in honeypot (`settings.honeypot`, `HONEYPOT_FIELD = 'website'`, payload carries
`honeypot: { field, value }`, filled ⇒ silent fake success), a `lead-capture` example
with browser tests, the `svelte-ignore` fixes of R-16, and a 0.3.0 CHANGELOG/README.
`docs/phases/reference/vendored-0.3.0.patch` is the exact diff of `src/`, `tests/`,
`README.md`, `CHANGELOG.md` between the two trees (package.json differs only in
`version`). Verified 2026-09-03: it applies cleanly on `e9f059b`; afterwards
`svelte-check --fail-on-warnings` reports 0 warnings and 41 unit tests pass.

## F. Minor (not scheduled)

- `TimeInput`: `placeholder` is a no-op on `type="time"`; a `step` below 60 s is ignored
  by `roundToStep`.
- `formatAnswer` returns raw ISO dates and `HH:MM` strings; no `Intl` localisation.
- `SummaryStep` renders an empty section for a step whose groups are all hidden.
- `allResponses` exposes the live `$state` proxy.
- Persisting a health questionnaire to `sessionStorage` by default is worth a README note.
